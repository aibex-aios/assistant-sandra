# Inhalt der Praxis

Der Leitfaden ist geladen. Die Praxis ist verfügbar: Lies das passende Dokument mit Read, bevor du zu seinem Thema etwas sagst oder tust. Jedes Dokument nennt seine Quellen im Playbook (Seite) und in der Spec von AIOS (Abschnitt).

| Datei | Inhalt | Lesen, wenn … |
|---|---|---|
| `@@Praxis/absicht.md` | `intent.md`: Fragen an den User, Vorlage, offene Fragen, Annahme | ein Durchlauf beginnt oder die Absicht geschrieben, korrigiert oder angenommen wird |
| `@@Praxis/spezifikation.md` | `spec.md`: Elemente, Grenzen, angewandte Vorgaben, Bedenken, Abnahmetest, Indikatoren | die Spezifikation geschrieben oder geprüft wird (nach T1) |
| `@@Praxis/vorgaben.md` | Vorgaben anwenden, Stand und Eigentümer, Bedenken entscheiden, neue Regel schreiben | eine Spec geschrieben wird, ein Bedenken entsteht oder der User eine Vorgabe festhalten will |
| `@@Praxis/implementierungsplan.md` | `plan.md`: die vier Teile, Abweichungen im selben Commit | der Plan geschrieben wird (nach T2) oder die Umsetzung vom Plan abweicht |
| `@@Praxis/pakete.md` | Namen, Manifest, Versionen, Aufbau je Typ, Lizenz, Vorlagen | ein Paket-Repo angelegt oder geändert wird (nach T3) |
| `@@Praxis/pruefen-und-probe.md` | Prüfliste, `test.md`, Release-Kandidat, Testprojekt, `--from`, `--to`, Abnahme, Freigabe-Version, Papierkorb | ein Paket geprüft, ein Kandidat getaggt (T4), erprobt, abgenommen oder freigegeben (T6) wird |
| `@@Praxis/masterspace.md` | `@/@Rule/` als neutrales Projektwissen statt Dateien eines Hosts | Konventionen eines Projekts festgehalten werden oder nach `CLAUDE.md` gefragt wird |
| `@@Praxis/luecken.md` | fehlende Bausteine von AIBOS und wie du sie benennst | das Playbook etwas verlangt, das AIBOS nicht neutral anbietet, oder eine Torstelle übersteuert wird |

Lies nur das Dokument, das zur Frage passt. Steht die Antwort weder dort noch in der Spec von AIOS, sag das, statt zu raten.
